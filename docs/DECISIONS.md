## D-01 Editor UI tech stack · decided (default)
- Date: 2026-10-31
- Question: Which UI technology for the editor? Constraints from the design: it embeds the mGBA core (C), calls Roslyn (.NET), has dark / light token themes, docking panels, a node graph, a tracker view and a code editor with an analyzer.
- Options: .NET (Avalonia / WPF / WinUI), web UI in a shell (Electron / Tauri) + .NET sidecar, Qt, Dear ImGui.
- Answer: **Avalonia 11 on .NET 10, C#**. One language for editor, toolchain and scripting; Roslyn runs in-process; the mGBA core is loaded with P/Invoke; Avalonia.Headless renders windows to bitmaps, so E2E tests and SHOT captures run without a desktop.

## D-02 C#-like scripting front end · decided (default)
- Date: 2026-10-31
- Question: Confirm the blueprint approach (Roslyn parse + analyzer, a C# subset translated to C++20, async to bytecode), and fix the supported C# features, the `fixed` (Figma: 24.8) and `fixed2` types, and the allowed generics (`Get<T>()`, `Is<T>()`).
- Options: none listed beyond confirming or changing the blueprint approach; the open points were the feature list, `fixed` / `fixed2` and the generics.
- Answer: Roslyn parses and binds user scripts against the `GBA` API reference assembly. A Roslyn analyzer enforces the GBA subset (GAE001-GAE006). A translator turns the bound syntax tree into C++20 (no exceptions, no RTTI). Methods marked `[Cutscene]` and `async` compile to Event Script VM bytecode instead.
- Supported subset (1.0): classes deriving from `Behaviour`, fields, properties with bodies, methods, `virtual` / `override`, `static` helpers, structs, enums, `int` / `bool` / `fixed` / `fixed2` / enums / `string` literals, `if` / `while` / `for` / `foreach` over arrays / `switch`, generics only on API calls (`Get<T>()`, `Is<T>()`), attributes `[Range]`, `[Cutscene]`, `[ScriptNative]`.
- `fixed` is 24.8 in a 32-bit int (as the Figma Script Editor text says); `fixed2` is two `fixed`.

## D-24 Where runtime logs go · decided (default)
- Date: 2026-10-31 (recorded for code that already existed; needs the user's confirmation)
- Question: Checklist item P2.11 says `Debug.Log` goes "to the mGBA debug-print interface", but the runtime writes logs to its own debug channel in EWRAM. Which one is the log path?
- Options: (a) mGBA's debug-print registers; (b) the AGB debug channel (`runtime/include/agb/debug.hpp`, magic `AGBDBG01`) read through emulator memory; (c) both.
- Answer: **(b)**. `Debug.Log`, `debug::log` / `logf`, `warnOnce` and failed asserts write to the log ring of the debug channel, which also carries the test status, the live actor table, profiler and debugger state. One mechanism serves the Console, the headless test runner, the live Inspector and the Debugger; the libretro host reads emulator memory and does not take text from the core's log interface, so mGBA debug-print text would not reach the editor; and the ROM does not depend on registers only mGBA has. Release builds strip the log text unless Project Settings · Build keeps it (`ARCHITECTURE.md` › Debug channel and logs).

## D-25 "Split into N palettes" for a 48-colour image · decided (default)
- Date: 2026-10-31
- Question: Figma's Import Asset · Errors card offers "Split into 3 palettes" for an image with 48 colours; the importer says "Split into 4 palettes".
- Options: none listed.
- Answer: **4**. A 4bpp GBA palette has 16 entries and entry 0 is transparent (for sprites, and for background tiles), so one palette holds 15 colours: 3 palettes hold at most 45, and every colour must be in at least one palette, so 48 colours need ceil(48 / 15) = 4. The message keeps "Split into 4 palettes"; 31 to 45 colours give "Split into 3 palettes". Test: `ImageConverterTests.FortyEightColoursNeedFourPalettesNotThree`. The Figma frame text is the one to change (Scope log).

## D-26 Performance targets: clean build, project open, Play start · decided (default)
- Date: 2026-10-31
- Question: G-PERF.03 asks for targets for a clean build, opening a project and starting Play, agreed in Phase 1. None were recorded, so nothing was measured against them.
- Options: (a) wall-clock targets for the Sky Hopper fixture on the build machine; (b) targets per asset count; (c) no targets.
- Answer: **(a)**, for Sky Hopper (5 scenes, 12 sprites, 12 scripts, 3 fonts, 9 audio files, 6 tables, 340 strings) on the build machine (16 GB, devkitARM with Ninja, `AGB_BUILD_JOBS=2`, other builds running):
  - clean build (build folder deleted, devkitARM compiles the runtime and every generated file, links, gbafix): **under 60 s**;
  - project open (the Opening Project steps: read the project and its scenes, load every asset, compile the scripts; the UI work of showing the scene is not included): **under 5 s**;
  - Play start (a build with no changes, load the ROM into the embedded mGBA core, run to the first game frame): **under 3 s**.
  The one-value script edit stays at under 1 s (G-PERF.02, T-D06). Tests: `FixtureBuildTests.FixtureBuildsCleanWithinTheTarget`, `ProjectOpensWithinTheTarget`, `PlayStartsWithinTheTarget`; each run appends its times to `build/perf-targets.txt`.
- Measured 2026-10-31: clean build 14.6 s, project open 0.2 s (scripting compiler already loaded in the process), Play start 0.4 s.
- Audio mixer (G-PERF.05), measured with the runtime profiler (Audio share of the 280,896-cycle frame, 8 mixing channels playing, a Release ROM, `RuntimeTextAudioTests.MixerShareFor8ChannelsAt21kHzIsMeasured`). The runtime now mixes at Project Settings · Audio "mixing rate" and channel count (GameDef `audioMixKHz`, and the build sizes Maxmod's buffers for them with `AGB_AUDIO_MIX_KHZ` / `AGB_AUDIO_CHANNELS`). Measured 2026-10-31:

  | Mixing rate | 21 kHz | 18 kHz | 16 kHz | 13 kHz | 10 kHz | 8 kHz |
  |---|---|---|---|---|---|---|
  | 8 channels | **14.49%** | 12.95% | 11.66% | 10.36% | 8.84% | **7.55%** |

  1 channel at 21 kHz: 5.57%; 8 channels of 32-sample loops: 14.51% (the loop length does not matter). The cost is about 3.2% that does not depend on the rate (Maxmod's module player, Thumb code in ROM) plus about 0.032% per sample of the frame (352 samples at 21 kHz): 1.27% per channel and 1.1% for clearing and writing out the mix. Figma's Audio window shows **6%** for 8 channels at 21 kHz; with Maxmod as linked that is out of reach at 21 kHz, and 8 channels stay above 6% at every Maxmod rate (lowest measured: 7.55% at 8 kHz). Maxmod's set-up has no cheaper mode: the mixer code and its mixing buffer are already in IWRAM; moving the 8-bit wave buffer from EWRAM to IWRAM would save about 0.25% for 1.4 KB of IWRAM. Getting to 6% needs fewer channels and a lower rate, or another mixer: a decision for the user. The test bounds are the measured figures rounded up (21 kHz 15%, 16 kHz 12%, 8 kHz 8%).
